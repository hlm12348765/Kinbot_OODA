本文件适用于 `docs/09_research/`。同时继承根 `AGENTS.md` 与 `docs/AGENTS.md`。

## 1. 研究材料的地位

- 研究文档默认是输入，不是产品或架构事实。
- 论文结论应收敛为候选字段、验证动作、失败模式或治理建议；只有经用户确认或阶段门评审后才能回写主线。
- 不得因单篇论文新增产品级在线组件、改变纯视觉主线，或把离线 world model / VLA 评测升级为在线安全裁决器。
- 具体 Phase 5 字段以对应每日纪要和整合评审为准，`AGENTS.md` 不再重复堆叠字段名。

## 2. arXiv 每日 / 每周纪要

输出位置：`docs/09_research/00_papers/`，文件名使用 `YYYY-MM-DD_kinbot_arxiv_daily.md`。

新增前：

1. 核对既有纪要的论文标题与 arXiv 编号，避免重复。
2. 以 `cs.RO/new` 作为正式 listing、entries 总数和 `new / cross / replacement` 计数口径；`cs.RO/recent` 只用于日期、近期待补录和重复主题复核。
3. 若当天没有新批次，在文档中写明检索日期、官方最新 listing 日期、条目数量和采用补录或周度复核的原因。

收录时：

- 优先 `3～5` 篇真正能增加 Kinbot 判断的强相关主卡片，不固定凑满数量；只有 `2～3` 篇有增量时就只收这些。
- 每张卡片至少包含摘要转述、Kinbot 问题映射、资源消耗、优劣势、推荐理由、来源链接和本轮 listing 口径。
- `replacement / cross submission` 只有新增 Kinbot 评测项、治理项或端侧资源判断时才进入主卡片。
- 其余有价值但增量不足的条目进入候选排除表，并说明未优先收录原因。
- 前序排除项后续可升级为补录主卡片，但必须写清新增理由。

同一 listing 连续复用时：

- 先列明前一轮已收录主卡片或直接重复主题。
- 接近饱和后切换为“日更补录 + 周度综合判断”，区分已饱和、接近成熟、仍需专题跟踪的主题。
- 近期待补录需注明 `cs.RO/recent` entry 日期、`Submitted on` 日期及补录属性，不得伪装成当日新批次。

稳定结构为：`检索口径 → 本轮总判断 → 论文卡片 → 候选排除表（采用时）→ 对 Kinbot 的落地 / 文档建议 → 来源`。总判断保留推荐优先级和本轮是否进入主线的明确说明。

## 3. A 档整合评审

- A / A- 论文整合评审写入 `00_papers/YYYY-MM-DD_kinbot_a_grade_paper_integrated_review.md`。
- 可配套同名主题的 SVG 全景图。
- 输出应收敛主题簇、主线影响判断和 Phase 5 候选字段包，不得直接冻结在线模块或验证模板。
- 同步 `00_papers/README.md`、本目录 `README.md` 与根 `CHANGELOG.md`。

## 4. VLN / NFM 专题

- `VLN → NFM`、长期记忆、导航基础问题和数据设计优先在 `07_vln_model_design/` 推进。
- 影响主线时，再回写 `01_vln_role_analysis_and_technical_plan.md`、相关架构文档与索引。
- 关键路线判断应通过独立评审或专项 issue 交叉校验。
- 引用年度总结中的 `SR / SPL / 成功率` 时必须保留任务类型、prompt、阈值、测评集和模型版本，不得直接比较不同任务与数据集。

## 5. 研究完成检查

- 新文档是否进入本级和父级 README。
- 是否记录真实检索口径、来源与时间。
- 是否清楚区分研究输入、候选建议和主线事实。
- 是否只提出最小验证动作，没有扩张在线系统。
- 是否需要回写主线、决策记录或 Linear；不需要时说明原因。

拆分前的论文专项字段清单和历史只读核查命令保留在 `docs/00_governance/agent_rules/AGENTS_v1.64_full_archive.md`，只在追溯旧规则时读取。
