## 一、项目概述

VLN（Vision-Language Navigation）技术研究项目以"从调研到落地"为主线，2025-08-04 完成立项评审（前期调研启动于 2025-05），跨年至 2026-05 结项收尾，实际推进周期约 12 个月。项目由硬件中心牵头，目标是为家庭室内场景的家用机器人构建可落地的 VLN 能力。

技术路线采取**零样本方案**与**基于模型方案**双线并行：

- **零样本方案**以 VLFM 为主线，在办公室 T 形场景下 20 次测试找物成功率达 80%，支持语音输入并在轮臂平台完成自主巡航找物全流程。

- **基于模型方案**以 Qwen3-VL-8B 为基座，新增 ASM 地图模态与深度图模态，通过 116,568 条自建多模态数据微调，将单步决策准确率从基线 0.34 提升至 0.79。在任务类型匹配的物体目标导航测评集上，原 prompt 自建集 SR 64.68%；改用结构化 Object Goal Navigation prompt 后，自建 objectnav 集 SR **62%（SPL 0.231）**， HM3D 无后处理 SR **32%(SPL 0.135)。**


真机侧在 JQR 轮臂平台、小车 + S100 平台完成找物/找人功能端到端打通；模型完成 int8 / int4-BNB / AWQ-4bit 三档量化与板端部署；仿真侧搭建 Habitat-sim 评估体系。



**项目核心可量化产出：**

- 4 个核心代码仓库（vln_qwen3_vl 主仓 + map_qwen 历史 + asm-vln 数据收集 + Habitat 评估程序）

- 116,568 条多模态训练数据，覆盖 49 个家居场景，每条含 4 路 RGB + 深度 + ASM + 2 帧历史

- 41 个苏州自采真实家居场景资产 + 8 个如视 GLB/USD 场景 + HM3D 标准场景（评估用，未加入训练）

- 一套从可导航终点 → 起点 → 路径 → 指令 → ASM 分区的自动标注流水线

- 多版本 VLN 模型权重




**关键指标说明（不同测评集 + 任务类型 + prompt 不可混淆）：**

> **注：**
>
> - **物体目标导航（ObjectNav）**：用户给"找椅子"这种类别名，模型找到任意一把椅子即成功；判定阈值 1 m。**这是本项目实际训练的任务。**
>
> - **实例图像目标导航（InstanceImageNav）**：用户给一张"特定那把椅子"的图，模型必须找到图中那一把（不能换别的椅子）；判定阈值 0.1 m。**与本项目训练目标不同，故标记为"任务不匹配"。**
>
>
> 同一个模型在两类任务上的表现不可直接对比。下表中标"任务不匹配"的行，仅作为"模型遇到非训练任务时的退化情况"参考。

|   |   |   |   |   |   |
|---|---|---|---|---|---|
|测评集|任务类型|Prompt|阈值|SR|SPL|
|自建早期评估集（含 ASM）|自建找物（总49 场景）|原|—|64.68% → 67.39%|—|
|objectnav_self|物体目标导航|优化|1 m|62%|0.231|
|objectnav_self|物体目标导航|原|1 m|2%|0|
|objectnav_hm3d_v2|物体目标导航|优化|1 m|32%|0.135|
|objectnav_hm3d_v2|物体目标导航|原|1 m|26%|0.074|
|instance_imagenav_hm3d_v3|实例图像目标导航（任务不匹配）|原|5 m|8–18%|0.022–0.155|
|instance_imagenav_hm3d_v3|实例图像目标导航（任务不匹配）|原|3 m|10%|0.073|

> **任务类型说明**：本项目实际任务为**物体目标导航**（按物体种类找物，1 m 阈值欧氏距离判定），不是**实例图像目标导航**（按图像找特定实例，0.1 m 阈值视点判定）。早期在 `instance_imagenav_hm3d_v3` 上得到 SR 8% 是任务类型错配的产物，并不能反映模型真实能力。在任务类型匹配的 `objectnav_self` 上，原 prompt 仅 2%，改用结构化的 Object Goal Navigation prompt（含同义词表、停止条件、决策策略）后跃升至 **62%**，证明项目阶段成果在匹配任务上有效。
>
> **基线说明**：单步决策 0.34 → 0.79 中，0.34 为微调前 Qwen3-VL-8B 在自建评估集上的零样本表现；0.79 为微调 2000 step 后的同集表现。中间真机迭代版本曾回退至 0.66（决策偏置），后续通过短路径接近 + 长路径优先探索两轮微调恢复并提升。
>
> 所有标准基准测试均使用 `Vln-Qwen3-VL-8B-Instruct-500-202602031754` 系列权重（含 bf16 与 int8 量化版），50 episode / 500 max_steps。

**调研三点核心结论决定了项目技术路线：**

1. **端侧实时场景下，零样本 + 云端大模型方案不可行**：所有零样本 SOTA 都依赖云端大模型（GPT-4 / Qwen-72B），推理 10s 级、网络依赖、调用成本高

2. **学术 SOTA 数据规模 7K–1.6 万，路径不可直接照搬**：但学术结论"4B 级 VLM 直训即可"在本项目场景需在更大数据上验证

3. **2025-10 后主流走 4B 端侧直训**：学术 SOTA 不再使用大模型权重蒸馏路线，全部在 3B/4B/8B 基座直接微调；这是后续技术路线评估时的重要外部参考


**后续持续跟踪的前沿方案**：ABot-N0、NavFoM、TrackVLA++、MM-Nav、NavRAG、Uni-Navid、Efficient-VLN、SeeNav-Agent、VLNVerse、MSNav。



## 四、技术路线与关键决策

### 4.1 双线推进策略

立项初期面临"快速验证机器人系统链路"与"深度建模导航能力"的平衡问题，决定双线并行：

- **零样本线（VLFM 为主）**：3 个月内验证传感、感知、运控、语义建图链路是否可用；不依赖模型训练

- **基于模型线（Qwen3-VL 端到端）**：长期主线，构建数据-训练-部署完整闭环


**结论**：双线策略是正确的。零样本线 2025-09 跑通后，整个机器人系统的多相机标定、ASM 建图、运控接口、人脸识别等基础设施都已落地，为后续基于模型方案的真机集成节省了大量调试时间。

> 零样本系统当前仍可作为主模型故障时的兜底链路。

### 4.2 零样本路线最终判断

四种零样本方案经复现得出共同缺陷：

|   |   |
|---|---|
|方案|核心缺陷|
|VLFM|推理稳定，但目标识别和语义理解受限于 GroundingDINO + BLIP-2，无法处理复杂指令|
|Sort3D|强依赖 LLM 工具调用；本地化为 Qwen2.5-VL-3B 后函数选错率高、目标点偏差 ±6%|
|UniGoal|物品空间关系强依赖大模型实时推断，物品多时准确性下降，单步耗时不可控|
|WMNav|单步需 3 次大模型调用，最短耗时 10s（仅模型调用），云端依赖、成本高|

**结论**：零样本方案无法满足端侧实时导航需求（< 2s、无网络依赖、输出可控）。**仅 VLFM 因架构简单可作为短期 demo 用；长期必须走端到端微调路线。**

### 4.4 深度模态取舍

**初版架构**（2025-11）：参考 MapNav，新增 `<map>` ASM 地图编码层 + `<depth>` 深度图编码层 + 投影层。

**消融实验后判断**（2025-12 至 2026-01）：深度模态对效果提升仅约 1%，但深度图数据量大、传输造成多相机推理通信瓶颈；实际部署推理已废弃，**主线只保留 RGB + ASM 两个模态**。

> 深度编码层代码保留在 vln_qwen3_vl 主分支，默认推理路径不启用。

### 4.5 TVI Token 方案复盘

**初衷**：为多相机方案中每张图增加角度标签（sin θ, cos θ），经 MLP 编码后叠加至 ViT patch embedding，期望模型不依赖 prompt 即能识别相机视角。

**结果**：在找人数据集上微调，500–1000 step 即出现过拟合；继续训练出现灾难性遗忘，原模型视觉能力退化。

**原因复盘**：

- sin θ/cos θ 经 MLP 投影后 element-wise 加到预训练的 ViT patch embedding 上，破坏了视觉先验分布

- rank-1 残差扰动相对于已对齐的 patch embedding 太大

- 训练数据中视角标签与导航决策的因果关系并不强（角度信息也可由文本 prompt 提供）


> 方案已废弃，代码保留在 `vln_qwen3_vl` 仓库的 `transformers-tvi` 分支。

### 4.6 找物识别后端迭代

找物的目标检测后端经历四次切换：

|   |   |   |
|---|---|---|
|时间|方案|切换原因|
|2025年9月|GroundingDINO|默认方案，开放词表检测|
|2025-12 至 2026-01|本地部署 30B VLM（用于检测）|DINO 在新场景下检测效果较差；30B/235B 大模型效果初步满足需求|
|2026年2月|回退到 DINO（30B 仅用于位置描述）|30B 实测高频误识别，prompt 优化无效；DINO 推进找物，30B 用于找物完成后描述位置|
|2026-03 至当前|WeDetect（最终上线方案）|真机部署适配 WeDetect，已集成至当前找物系统|

> 当前生产链路使用 **WeDetect**；30B 模型保留用于找到目标后的位置描述（"在桌子右侧"）。

**单条数据构成**（116K 数据集）：

- `map`: 1 张 ASM 鸟瞰地图

**已知数据分布问题：**

- 直行 53.1%、转向 45.9%、**停止仅 1.0%**——动作分布严重不均衡

    > 此前模型容易出现过早停止现象，所以针对问题造的“极端数据”，但即使这样模型也还是会容易不输出停止，所以在策略上还是用了工程化的方法强行兜底；这样过度失衡的数据分布理论上是不太合理的。

- 直行样本中相机朝向**对准路径下一个点而非终点**，导致目标可见性弱（AI Review发现）

    > 可能带来的风险是未到识别正确物体却判断已找到

- 历史脚本中存在 `max(2.00, 实际距离)` 直行下限，模型从未见过短距直行样本（AI Review发现）

    > 可能带来的风险是模型没见过短距样本，无法精细的接近物体容易冲过头

- 上述问题的原因来自**数据生成脚本的逻辑设计**（非采集环节），解决方案在下一阶段规划中体现

### 6.2 VLN 服务框架

**接口设计：**

- **WebSocket**：与上层运动系统交互（接收找物/找人指令、返回状态）

- **ROS2 Action**：与下层大导航交互（发送动作命令、接收执行反馈）

- **找物/找人统一接口**：人脸引擎校验 + 本地记录 + ASM 图标注逻辑


**找人两段式逻辑：**

1. 模型导航至人附近（基于人形 bbox）

2. 旋转检索 + 人脸识别引擎判定身份（face_recognition 库）

3. 第二段导航时后视相机出现目标人则旋转 180°

4. 找人导航失败时返回离目标人距离


**异常处理：**

- 语义系统接收人脸/人形 bbox 空值异常处理

- bbox 坐标转换流程与物品语义合并

- 模型停止结果幻觉校验（避免提前结束任务）

- 当前靠近的人不是目标人时继续推理而非停止

- 日志按日期轮转记录，运行状态可追踪

**关键观察：**

1. **任务类型决定上限**：本项目模型针对 objectnav 训练，在 instance_imagenav（图像匹配任务）上表现差是任务错配，不能等同于"模型不行"。

2. **结构化 prompt 价值显著**：`objectnav_self` 上原 prompt 2% → 优化 prompt 62%，证明 prompt 工程是当前 8B 量级模型上最具性价比的优化方向。

3. **量化对结果影响小**：int8 与 bf16 在 50 ep 测试中差异处于噪声范围内。

4. **UniGoal 框架 + 本项目模型**在 instance_imagenav 上达到 60%，说明把本项目模型作为 VLM 工具嵌入零样本 pipeline 也是一条可行的路径。

5. **失败模式集中在三类**：判定距离过远（提前停止）、判定错误（未识别正确物体却判已找到）、长输出退化（一次罗列上百物体重复）。

6. **数据集口径差异**：UniGoal 使用 instance_imagenav（视点判定）+ 测地距离，本项目自建集使用 objectnav（1 m 欧氏距离）。两者评估标准不同，分数不能直接比较。

## 九、遗留问题与后续工作建议

### 9.1 遗留问题

**模型能力：**

- **HM3D objectnav SR 仅 32%（优化 prompt 后）**：自建集 62% 与 HM3D 32% 之间存在 30 pp 差距，说明跨场景泛化能力不足；评估集替换、模型替换、提示词进一步优化是下阶段关键

- **判定停止时机不准**：测试中失败案例集中在"距离过远（≥3 m）就判定停止"和"未识别正确物体却判已找到"，对应到达判定模块（VLM 描述 + 文本相符性）边界条件设计不足

- **长输出退化（偶发）**：测试中观察到 VLM 描述请求偶发产生上百物体重复罗列，模型对长尾噪声不稳健

- **优化 prompt 推理速度变慢**：精细化 prompt 输入 token 增多，且观察到量化版输出反而比 bf16 慢的反常现象，需排查

- **多步推理能力不足**：输出仍是原子动作而非语义子目标

- **ASM 地图理解弱**：模型无法判断可通行性、不理解自身本体大小

- **多视角融合能力不足**：缺乏多相机预训练数据

- **单步推理耗时（4090）0.6–1.8s**，主要瓶颈在 ViT，走走停停的用户体验不佳；Orin NX 板端 AWQ-4bit 实测耗时见性能评估文档


**数据体系：**

- **动作分布严重不均衡**：直行 53.1%、转向 45.9%、停止仅 1.0%；标注步长偏小（`max(2.00, 实际距离)` 直行下限）导致模型偏向"小步推进"和"看到就停"，根因分析与重构建议见独立的早停问题分析文档

- **人物身份确认链路不完整**：多描述、唯一性、Prompt 设计

- **小物体（手机等）识别率极低**

- **缺乏无监督自动标注、世界模型生成数据、动态场景数据**

- **缺乏统一数据协议和分析****日志****体系**


**仿真与工程：**

- Habitat 无法导入真实本体、无法做强化学习

- Isaac Sim 如视模型需定制化开发（房屋可视化与 agent 移动冲突）

- Real2Sim：如视 USD 模型分辨率/拓扑与真实场景差距大，导致仿真训练 → 真机泛化损失

- 网络延迟影响多传感器同步


**外部合作未结收尾项：**

- 如视生成式场景未签合同

- 群核科技报价未提供


**未在主线但已跑通流程的探索（2026-04）：**

- lingbotmap 算法复现：全流程已跑通，效果测试未完成

## 十、项目反思与经验沉淀

### 10.1 决策回看

**事后看做对的：**

- **零样本 + 端到端双线并行**：让基础设施（标定、ASM、运控、人脸）在主模型成熟前就已落地，主模型上来即可集成

- **2025-11 切换到 Qwen3-VL-8B**：相比 Qwen2.5-VL 视觉-语言融合更紧，2000 step 即从 0.34 提到 0.79

- **找物检测后端最终回到工程化方案 WeDetect**：避免因过度依赖 30B VLM 导致系统不稳定




**事后看可改进的：**

- **评估集任务类型必须匹配训练任务**：早期用 `instance_imagenav` 评估按物体种类训练的模型，"SR 8%"对外汇报后被解读为"模型不行"，但本质上是任务错配。2026-02 切回任务匹配的 `objectnav_self` 上（优化 prompt 后 SR 62%）才看到模型真实能力。

- **数据动作分布问题应在 2025-11 初版数据生成时就发现**：起步阶段缺少对样本均衡性的量化检查，导致 116K 数据集存在系统性偏置；后续在数据 pipeline 加入分布报告作为 CI 检查项

- **TVI Token 不应在大数据集 + 全量微调上直接试**：先做小规模 LoRA 验证，可避免一轮训练资源浪费




### 10.2 流程教训

- **众包标注首版有效率 55.1% / 66.7%**：标注需求文档对边界 case 描述不足；后续应在合同前先做 50 条试标注 + 联合复核

- **外部合作（如视、光轮、群核）报价/合同周期长**：建议同时启动 3+ 家供应商对比，避免单点依赖

- **真机问题的根因往往在数据**：早停问题最初被认为是模型问题，多轮微调无效后才回头追到数据生成脚本——遇到模型异常时优先检查数据 pipeline
