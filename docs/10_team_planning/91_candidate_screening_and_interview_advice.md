## 3. 候选人逐一判断

### 3.1 王世轩

对应岗位：

1. `01` 架构师（高级开发人员）
2. 实质上对应应用后端 / AI 融合架构岗位

简历快照：

1. 本硕背景，硕士来自天津大学。
2. 2021 年起在华为任软件开发高级工程师，主要经历集中在数据工程、BI、自研平台、规则引擎和架构重构。
3. 当前有模块 leader / MDE 经验，具备一定带小团队和架构演进经验。

岗位匹配判断：

1. 与岗位对口的部分：
   - Java 后端和分布式能力较强。
   - 有系统性能优化、模块架构演进、数据平台能力建设经验。
   - 有一定 AI 工程能力，尤其偏数据工程、训练管理、特征工程、作业流编排。
2. 不足的部分：
   - 工作年限略短，严格看仍偏年轻型候选人。
   - 简历里对“大模型应用后端、Agent 编排、多模态 / 语音落地、智能终端”支撑证据不够强。
   - 更像平台 / 数据 / BI 架构型背景，不完全等于家庭机器人应用后端架构 owner。
   - 机器人、智能硬件、多模态交互系统的直接经验缺失。

筛选建议：

1. `B+ 档，可推进`
2. 面试表现证明其系统工程、端云协同、可观测性和平台化思维强于简历呈现，值得继续推进。
3. 但如果岗位目标是“立即独立承担家庭机器人应用后端 owner”，当前证据仍不够硬。
4. 如果岗位可以接受“强平台 / 后端底子 + AI 工程化思维 + 需要补消费级设备后端经验”，则值得继续看。

主要优势：

1. 后端基础扎实，能讲清系统性能、模块分层、数据架构和效率提升。
2. 有把一次项目沉淀成平台能力的意识。
3. 有团队协作、带小组和推动重构的经历。
4. 首轮面试证明其对端云链路、日志监控追踪、平台与业务边界、AI 代码质量控制都有较成熟方法论。
5. 对“统一底座 + 上层适配层”的架构思路表达清晰，具备一定产品系统抽象能力。

主要风险：

1. 与岗位 JD 要求的“AI 能力 + 业务后端 + 多模态 / 语音 / 智能终端”之间仍有距离。
2. 目前更像企业软件 / 数据平台骨干，而不是家庭机器人应用后端架构 owner。
3. 对设备联机、边云协同、`OTA`、时延与可靠性约束等消费级软硬一体后端经验仍偏少。
4. 管理经验和结果量化表达还不够强，CTO 二面要防止被“华为 + 架构 + AI 工程化”标签抬高预期。

CTO 面试结论吸收：

1. 已完成 `CTO 二面`，确认其在系统工程、端云协同、可观测性、平台边界和 AI 工程化方法论上明显强于简历呈现。
2. 当前问题已不再是“是否具备基本架构视野”，而是“是否具备家庭机器人应用后端 owner 所需的产品型闭环经验”。
3. 现阶段不建议直接以 CTO 结论进入最终录用判断，仍需一轮岗位聚焦深面补齐设备联机、边云协同和消费级软硬一体后端经验验证。

后续面试建议：

1. 下一轮建议由应用后端 / 平台负责人主问，重点深挖其在设备联机、边云协同、稳定性、灰度发布和观测闭环上的真实能力。
2. 若该轮验证其具备产品型后端 owner 潜力，可回到最终评审；若更偏平台 / 数据工程，应及时转入并行岗位池，而不是继续按 `01` 强推。
3. 当前不建议再安排一轮同类型 CTO 面，除非后续出现重大分歧点需要复核。

CTO 二面候选问题（`10` 道供选择）：

1. 技术能力：你过去做过最复杂的后端 / 平台系统是什么？其中你亲自设计和拍板的核心模块有哪些？
2. 技术能力：你在 AI 工程化里，真正落过哪些 `LLM / Agent / 多模态` 能力？哪些是直接面向业务，哪些只是支撑训练和数据流？
3. 系统工程：如果一个“端侧请求 -> 云端编排 -> 多端回执”链路在现场频繁失败，你会怎样设计事务 ID、日志、监控、追踪与排障入口？
4. 架构思考：你过去做的平台架构，如何迁移到一个“智能终端 + App + 云服务 + AI 能力”的产品系统？哪些思路可以直接复用，哪些必须重做？
5. 架构思考：如果让你从 `0` 到 `1` 设计一个“AI 能力 + 业务后端”融合系统，你会如何拆核心服务边界？你会先固化哪些能力，后延哪些能力？
6. 行业认识：你认为企业数据 / 平台系统和家庭机器人应用后端最大的本质差异是什么？为什么这会影响架构决策？
7. 产品思维：面对一个软硬一体的新产品后端，你会优先保证“可观测性、稳定性、交付效率、单点体验”中的哪两项？为什么？
8. 协作能力：讲一个你和产品、算法、客户端或运维团队发生明显分歧的例子。你最终怎样推动一个可交付的共同方案？
9. owner 意识：你更像平台型架构师，还是业务型架构师？请拿一个项目证明你不是只负责协调，而是对结果真正负责。
10. 风险与自我认知：如果你来做这个岗位，你目前最不充分的能力是什么？你会怎样通过前几个月的项目安排把它补上？

综合建议：

1. `建议继续推进到岗位聚焦深面`
2. `可作为 01 岗位的中高优先级候选人继续观察，但暂不建议直接快速推进`
3. `如果后续验证更偏平台 / 数据工程，也可转入并行岗位池保留`

对岗位 `11 / 12` 的匹配补充判断：

1. 对岗位 `11`：`部分适配，但不建议作为主推候选人`。他更像 Agent 配套的后端 / 平台支撑型人才，而不是当前岗位最想要的 Agent 应用工程师。
2. 对岗位 `12`：`不适配`。缺少 Linux 应用、中间件、C/C++、多线程网络通信和系统级调试的直接证据。

5. 能够清晰阐明 `SE` 与硬件、结构、系统软件等角色的边界，且有实际组织建设经验。

主要风险：
