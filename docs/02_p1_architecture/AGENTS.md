## 3. L1 冻结基线

后续设计必须保持以下不变量：

1. **唯一根责任。** A0 对根任务、跨业务优先级和用户承诺负责，但不接管 TaskWorker 的局部规划或实时控制。
2. **契约只有一个 Owner。** 四个基础业务 Agent 拥有长期业务契约；TaskWorker 是持有一次有界任务契约的临时 AgentCell。
3. **AgentCell 形式一致。** 所有被称为 Agent 的实体复用 Physical Agent 七元组；契约、租约、Skill、下级 Agent 和生命周期是属性或约束，不扩充七元组。
4. **Skill 按能力复用。** RobotSkill 是能力接口，内部可以包含 AgentCell；内部 Agent 只拥有执行子契约，不能取得调用方的业务契约。
5. **共享语义与局部状态分开。** O3 管理 SharedState、SharedMemory 和 Evidence；Agent 的中间推断和局部工作状态不是共享事实。
6. **策略与运行机制分开。** Agent 决定业务策略；AP3 管 TaskWorker、资源、租约、隔离和运行机制，不解释业务优先级。
7. **外部操作必须受控。** 信息操作和物理动作都经过 G3；G3 只能许可、收紧、选择预先允许的等价操作、拒绝或撤销，不能成为第二个业务规划器。
8. **硬安全独立。** F1 直接读取实时物理信号并产生最终安全动作；A0、G3 和大模型不进入电机级实时闭环。
9. **反馈返回任务 Owner。** TaskWorker 只依据许可后的实际操作、实际结果、共享状态和证据更新任务状态；不能把候选动作当成已经执行。
10. **重大事件逐级处理。** 正常业务升级采用 `执行与治理实体 → TaskWorker → A0 → 受影响实体`；显式用户意图输入和预定义紧急契约不等同于执行层越级上报。
11. **持续感知保持闭环。** RobotSkillSystem 执行语义感知相关的 `P-P1/I-P1`，O3 从 `I2/Evidence` 开始执行 `I-P2`；F1 保持安全与本体实时感知。
12. **多时间尺度解耦。** Navigation 等 Skill 能在本地响应实时变化；跨时钟实体只读取仍然有效的状态版本。

始终禁止：自由多 Agent 全连接、同一契约多个有效 Owner、外部系统直控本体、子 Agent 自行扩大权限、模型输出直达执行器，以及用未交付能力伪造成功闭环。

## 4. L2 下探规则

L2 可以细化实现，但每项设计必须回答：

- 它属于哪个 L1 实体，谁对结果负责？
- 它参与哪些 `I-P/P-P` 过程，读取和产生哪些 `I/P` 操作数？
- 它位于哪一类闭环和哪个时间尺度？
- 它使用 SharedState、SharedMemory、Evidence，还是只维护局部工作状态？
- 正常结果、拒绝、超时、撤销、恢复和责任交接如何返回 Owner？
- 单点崩溃、错误、延迟、过载或分裂运行时，故障被限制在哪里？
- 它对应哪个团队或责任人，能否独立开发、验证和发布？

若 L2 设计必须改变 L1 实体、责任、主关系或不变量，不得以“实现细节”直接写入。先提出架构变更，说明触发它的反例、受影响的冻结结论和迁移代价，经评审后再修改基线。

## 5. 实体判定与复杂度控制

新增或升级 AgentCell 时，必须证明它：

1. 拥有明确、持续的任务契约和唯一责任；
2. 维护独立状态并能自主选择行动；
3. 负责完成、失败、验证、恢复和生命周期；
4. 不能由已有 Agent 加 TaskWorker、Workflow、RobotSkill、模型、服务或确定性组件更简单地承担。

新增基础业务 Agent 还必须具备独立稳定的用户价值、跨任务与跨会话责任、长期业务状态或规则、独立指标和组织责任人。缺少任一项，默认使用 TaskWorker 或 RobotSkill。

每次实质修改架构只做一次复杂度自检：

> 新增的实体或关系阻断了哪个可验证的失效场景？

答不出来时，优先删除该复杂度。能够通过收紧契约、复用 Skill、增加 TaskWorker 或明确状态归属解决的问题，不新增固定 L1 实体。

## 6. 修改与验收

- 先解释问题产生的原因，再提出解决办法。
- 已确认基线、候选变更和实现假设必须明确区分。
- 系统级变更先写主架构文档，再检查状态、安全、运行时、功能验证和下游方案是否需要同步。
- 新增关系必须回溯 L0 过程与操作数，并映射到 Agent 局部、契约履约、信息操作、物理任务、F1 硬安全、运行治理、持续感知七类闭环之一。
- 用具体失效场景验收，不以“各有利弊”代替结论。
- 公式、SysML、SVG、Draw.io 和正文必须语义一致；图示维护方式继承 `docs/AGENTS.md`，不在本文件重复。
- 未经用户明确要求，不修改外部 Issue 状态，不把文档设计写成已经实现或实机验证。
